# Retire `<slug>`

Reached from `fork-change` (`retire <slug>`, or step 3 finds the change removes a customization). Guardrails from `SKILL.md` hold: never push; never `git stash`, `git reset`, `git checkout -- <file>` or `git commit --amend`; never `--no-verify` unless the user says so. `<trunk>` and `<upstream>` are the **Trunk** and **Upstream** values in `.omp/rules/commands.md`. Base: `b=$(git merge-base HEAD <upstream>)`; failure → stop.

On the current branch, or `git fetch origin && git switch -c chore/retire-<slug> origin/<trunk>` when retiring on its own. Retiring on its own (`retire <slug>`): `git status --porcelain` must be empty first. Routed here from fork-change step 3: the staged change from step 1 is this retirement's work, so skip the clean-tree check and go on from Which kind.

1. **Which kind**, before touching anything. *Removing the behavior*: the fork no longer wants it. *Replaced by upstream*: upstream supplies it now; only the fork's leftover delta goes, and only once upstream's change is in a release the fork merged (`git merge-base --is-ancestor <upstream commit> origin/<trunk>`; upstream's development branch is not enough). Ancestry is not enough either (a Keep-mine port records it but drops upstream's code): read `git show <upstream commit>` against the entry's Files in `HEAD`; upstream's version missing → stop. A port already took upstream's version → revert nothing; delete the entry and remove leftovers.
2. **Save** the entry's Verify and Check, each to a temp file, and a copy of any script the Verify runs.
3. **Find the commits.**
   ```sh
   git log --format='%h %s' --grep='^Fork-Flow-Change: <slug>$' "$b"..HEAD
   git log --no-merges --invert-grep --grep='^Fork-Flow-Port' --format='%h %s' "$b"..HEAD -- <Files>
   git diff --diff-filter=A --name-only "$b" HEAD -- <Files>
   ```
   The second catches commits without the trailer; the ranges keep upstream out (an upstreamed fork commit keeps its trailer) and `--invert-grep` drops old single-parent port squashes. Port merges also re-applied fork code; step 5's diff catches it. Read each commit's full path list (`git show --name-status --format= <sha>`) and ledger hunks, not its trailers: a commit with only this trailer can still change a kit rule or an ADR. The third lists added files: each must be gone after the revert, or kept on purpose; the base lacks them, so a kept one is fork-owned and needs no entry. Show it all; confirm.
4. **Revert**, newest first. `git revert --no-commit <sha>` only when every path and ledger hunk in it belongs to this retirement. Otherwise only this entry's own paths: `git show --binary --format= <sha> -- <paths> | git apply -R -3` (without `--binary` a binary change fails), leaving out files another entry lists; in those, remove only this entry's hunks by hand (`git show <sha> -- <file>`). *Replaced by upstream* removes only the fork delta: each file only this entry owns ends equal to the merged upstream version (`git diff --quiet "$b" -- <file>`), in shared files only this entry's hunks go, and never revert a commit whose revert removes upstream's copy of the behavior. Resolve conflicts toward today's code; a `.fork/CHANGES.md` conflict (an old ledger hunk) → `git restore --source=HEAD --staged --worktree -- .fork/CHANGES.md`. A database migration production already ran is never reverted or deleted: keep it, add one that undoes its effect, and move both into the Files and Verify of an entry that keeps retained migrations. Then delete the entry.
5. **Prove it.** `git diff "$b" -- <Files>` shows no hunk of it left (retained migrations aside). Run each saved command with `bash <file> </dev/null` from the repository root; a Verify script the revert deleted is put back at its path for the run, then removed again. *Removing*: the Verify fails on its own assertion (a missing program exits 1 or 127 and proves nothing), and the Check, if it still applies, shows the behavior gone. *Replaced by upstream*: the Verify, or the Check when the Verify names fork-only files, still passes, because upstream supplies it. A failing Verify is never permission to remove upstream's implementation.
6. **`SKILL.md` steps 4 and 6–8.** Step 7's Checks cover only touched entries that still exist (the retired slug is unknown now). Subject `custom: retire <slug> — <why>`, trailer `Fork-Flow-Change: <slug>` (without it `ship` step 1 folds the commit as WIP).
7. Land through `ship`.
